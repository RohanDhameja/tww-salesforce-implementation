# Delivery roadmap

## Phase 0 — Foundation and security architecture

- Baseline the current `twwdev` configuration read-only.
- Normalize personas, licenses, roles, profiles, permission sets, and sharing.
- Allocate the 10 internal licenses to named users or approved positions.
- Define sensitive-data policy.
- Assess the existing hosted website and select React versus Salesforce-native boundaries.
- Establish source control, deployment, testing, and worklog practices.

Exit criteria: approved security matrix, license allocation, architecture decision, and current-state baseline.

## Phase 1 — Core operations and priority journeys

- Deliver approved high-value Phase 1 stories.
- Implement feature-level CRUD, field security, and sharing alongside each feature.
- Prioritize donation, expense, project, volunteer, beneficiary/student, and core reporting journeys according to the approved backlog.
- Deliver React experiences where justified by the Phase 0 architecture.

Exit criteria: priority journeys pass functional, security, accessibility, and mobile validation.

## Phase 2 — Extended workflows and engagement

- Add approved workflows, compliance, outreach, reporting, and portal capabilities.
- Harden approval, notification, document, and external-user experiences.

Exit criteria: Phase 2 acceptance criteria and persona-based regression tests pass.

## Phase 3 — Optional and advanced capabilities

- Evaluate optional integrations and advanced reporting against cost, licenses, security, and value.
- Examples include Box alternatives, Okta, Canva, mobile scenarios, and executive presentation automation.

Exit criteria: each capability has a separately approved business case and operating model.
