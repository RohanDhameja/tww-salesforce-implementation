# Test strategy

## Test dimensions

- Functional acceptance criteria
- Persona-based CRUD and field security
- Record ownership and sharing
- Negative-access scenarios
- Automation, approvals, and integration behavior
- Responsive web behavior
- Accessibility and keyboard operation
- Performance and reliability
- Regression across phases

## Security testing rule

Do not accept a feature solely because it works for a System Administrator. Test with the intended least-privilege persona and verify that prohibited actions and sensitive fields remain unavailable.

## Evidence

Each worklog or pull request must identify:

- Environment and test user/persona
- Preconditions and test data classification
- Steps and expected result
- Actual result
- Defects or exceptions
- Retest result
